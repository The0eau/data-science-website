Implementation

0. Engines: SQLite vs PostgreSQL

SQL is the language, but you need an engine to run it. Here is how they differ in usage:

SQLite (Featherweight)

A serverless engine that stores everything in a single file (.db) on your device.

  • Usage: Mobile apps, IoT, local software, quick prototyping.
  • Pro: Zero configuration, portable, fast reads.
  • Limit: Not for high-concurrency web traffic.

PostgreSQL (Heavyweight)

A powerful Client-Server system running as a background service.

  • Usage: Complex web apps (Instagram), Fintech, Big Data, GIS.
  • Pro: Massive scaling, advanced security, strict integrity.
  • Limit: Requires setup and server resources.
Schema

1. Data Definition (DDL)

Used to define, modify, or delete the structure of your database objects.

-- Create a new table
CREATE TABLE users (
    id INTEGER PRIMARY KEY,
    username VARCHAR(50) NOT NULL,
    email TEXT UNIQUE,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- Add a new column
ALTER TABLE users ADD COLUMN bio TEXT;

-- Delete the entire table
DROP TABLE users;
Manipulation

2. Data Manipulation (DML)

Commands to manage the rows (data) inside your tables.

Insert & Update

-- Adding data
INSERT INTO users (username, email) 
VALUES ('johndoe', 'john@example.com');

-- Modifying data
UPDATE users 
SET bio = 'Software Engineer' 
WHERE username = 'johndoe';

Delete

DELETE FROM users WHERE id = 1;
Retrieval

3. Data Querying (DQL)

The most frequent operation: fetching data based on specific criteria.

SELECT username, email 
FROM users 
WHERE email LIKE '%@gmail.com'
ORDER BY created_at DESC
LIMIT 5;

Analysis

4. Aggregates & Joins

Combining multiple tables and calculating statistics.

-- Counting items by category
SELECT country, COUNT(*) 
FROM users 
GROUP BY country;

-- Joining Users and Orders tables
SELECT users.username, orders.amount
FROM users
INNER JOIN orders ON users.id = orders.user_id;
